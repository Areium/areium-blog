源码解析

配置中的 ray、mp、uni、external_launcher 分别选择相应 Executor 实现。这里不是选择模型结构或 attention 算子，而是选择怎样组织 Worker 的执行与通信。

逐步拆解

  1. 相同 execute_model 接口背后可以是本进程直接调用，也可以是跨进程协调；只读抽象类无法解释每一种部署的实际结果归并方式。
  2. 前后的其他分支还支持合法的自定义 Executor 类或导入路径。后端必须符合 Executor 契约，不是给任意 Python 类一个名字就能工作。
通俗理解

总经理使用同一套“开始生产、取结果”指令，但车间可以在隔壁，也可以分布在几个城市。后端决定指令怎样送达，并不决定产品本身的配方。

源码解析

initialize_from_config 向 Worker 发初始化命令；compile_or_warm_up_model 负责下发编译或预热，并收集 Worker 的耗时。对于并行编译，语言模型耗时取各 Worker 的最大值。

逐步拆解

  1. 这里调用的是 collective_rpc 的统一入口，实际参数分配和调用组织由具体后端实现。不能把列表参数理解成每个 Worker 都一定直接采用整份列表。
  2. 预热、图捕获与缓存建立属于准备阶段，不是每个用户 token 都从头编译一次。取 max 而非 sum 体现各 Worker 可并行完成准备工作。
通俗理解

开工前通知所有车间把机器准备好。若几家车间同时准备，总部等的是最慢一家准备完成，而不是把每家的准备时间依次相加。

02 · 前向和采样是两种执行命令

源码解析

基类将 SchedulerOutput 作为参数发给 Worker 的 execute_model，并从后端返回结构中取相应输出。输入仍然是计划，不是这里已经整理好的 input_ids tensor。

逐步拆解

  1. 这段是基类实现，具体后端可能重写它来处理 Future、返回值选择或多 Worker 汇总。不能据 return output[0] 断言所有分布式路径都只执行或读取第 0 张卡。
  2. ModelRunnerOutput、None、Future 都出现在返回契约里。调用方必须知道当前后端和执行阶段，不能把所有返回值都当成立刻可读的 token 列表。
通俗理解

总经理把派工单交给车间协调员。协调员按后端规则把任务分派并整理回执，而不是自己在办公桌上替工人完成所有加工。

逐步拆解

  1. grammar_output 可以为 None，表示没有这份结构化约束；并不意味着生成过程没有其他 sampling 参数，后者已经在请求和批次状态中保存。
  2. 如果执行阶段采用分离采样路径，EngineCore 会接着调用这个接口。部分其他模型任务或执行路径可直接返回结果，不能强制所有返回值再采样一次。
通俗理解

机器先产生各候选方案的分数，然后另一步按规则选一个。总经理可以分别要求“先算分数”和“按这份格式约束挑选”，而不是把两件事混成无法区分的命令。

03 · 单进程后端如何落实抽象接口

UniProcExecutor.collective_rpc：同步路径executor/uniproc_executor.py · L99–106 ↗
99        if kwargs is None:100            kwargs = {}101102        if not non_block:103            result = run_method(self.driver_worker, method, args, kwargs)104            if isinstance(result, AsyncModelRunnerOutput):105                result = result.get_output()106            return result if single_value else [result]
源码解析

单进程后端直接 run_method(driver_worker,...)。若返回 AsyncModelRunnerOutput，则同步路径调用 get_output 等待并物化；最后按 single_value 决定直接返回对象还是包成列表。

逐步拆解

  1. collective_rpc 的名字不保证一定发生网络通信：此处就是同进程方法调用。统一名字让 EngineCore 不需要为每种后端重写业务流程。
  2. AsyncModelRunnerOutput 是执行结果的延迟收集包装，不等价于 asyncio 协程。同步分支在返回前主动拿到可消费输出。
通俗理解

办公室和车间就在同一处，协调员直接走过去调用方法。若工人给的是“待整理的回执”，同步取件就当场等它整理好再交给上级。

UniProcExecutor.collective_rpc：非阻塞返回形式executor/uniproc_executor.py · L108–117 ↗

源码解析

非阻塞分支依然先调用 run_method。若结果是异步 Runner 输出，包成 AsyncOutputFuture；否则把已经得到的值放进 Future，异常也存进 Future。

逐步拆解

  1. non_block 不一定代表启动新 Python 线程。这里的函数调用本身仍执行，只是结果可能以 future 或异步拷贝包装形式交付。
  2. set_exception 确保错误沿同一等待接口传播。不能看到一个 Future 对象就默认模型已成功完成。
通俗理解

协调员可以先给你一张取件凭证。有些凭证对应尚未收齐的材料，有些其实已经办好了；“拿到凭证”说明返回方式统一，不代表每次都新开了一个后台工人。

04 · 具体后端的返回契约优先于抽象猜测

UniProcExecutor.execute_model：直接值与早期失败executor/uniproc_executor.py · L119–131 ↗
119    def execute_model(  # type: ignore[override]120        self, scheduler_output: SchedulerOutput, non_block: bool = False121    ) -> ModelRunnerOutput | None | Future[ModelRunnerOutput | None]:122        output = self.collective_rpc(123            "execute_model",124            args=(scheduler_output,),125            non_block=non_block,126            single_value=True,127        )128        # In non-blocking mode, surface any exception as early as possible.129        if non_block and output.done():130            # Raise the exception in-line if the task failed.131            output.result()
源码解析

UniProcExecutor 重写 execute_model，调用自身 collective_rpc 并要求 single_value=True。在 non_block 情况下，如果 future 已完成，就立即调用 result 暴露异常。

逐步拆解

  1. single_value 避免上层再次从列表里取值，使返回形式符合 EngineCore 需要的 ModelRunnerOutput 或其 Future。
  2. 这段在输出已就绪时检查失败，后面仍会返回 output。早发现错误可以减少核心继续使用错误状态，但不改变 Scheduler 的资源规划职责。
通俗理解

拿到凭证时如果已经明确写着失败，协调员就当场告诉你，不会让你排很久才发现。凭证封装是运输细节，排班员仍只负责安排工作。
